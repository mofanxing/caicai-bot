## 任务执行

DeepSeek Harness 0.2.2-rc.3 / 0.2.2-rc.5 适配、任务中心、聊天显式派发、按需增量汇报及桌面 worker 管理已实现；隔离 Git 项目的失败测试修复与运行中取消已通过真实验收。执行模型与认证沿用 Harness 自己的配置。自然语言自动建任务和任务结束后的一次性语音提醒已接通；执行中关键节点播报和完整桌面人工任务验收待完成；Codex 历史原型保留，真实接入后置。

进入“任务中心”点击“选择文件夹”登记 Git 项目并启用 DeepSeek 插件；登记可删除，不删除磁盘文件，有待执行任务时需先取消或等其完成。在聊天直接说“帮我修复 XX 项目的登录问题并运行测试”即可自动建任务；不明确的项目会先追问。仍可点击“交给菜菜执行”或在任务中心手动创建。详情展示真实步骤、日志、文件改动、检查结果和取消入口；“让菜菜汇报”按需调用当前会话模型。

任务结束后只用所属会话已选音色简短提醒一次，不写入聊天、不显示播放或重播按钮；播放自然结束后删除音频文件和语音任务，删除失败只重试清理，不重复播放。开启“自动朗读”后，收起窗口仍能播报；未选音色时不生成提醒。聊天内隐藏已结束任务卡片，详情在任务中心保留 5 天，活动任务与未核查中断不自动删除。

桌面自启后端托管独立 worker，退出时释放；复用外部后端时，worker 由外部管理。收起聊天窗口不取消任务。配置见 [Harness 接入](../docs/DEEPSEEK_HARNESS.md) 和 [任务运行时](../docs/TASK_RUNTIME.md)。真实 Electron 聊天隔离验收包含任务中心页面加载，截图保存为 .data/tasks-smoke.png，此检查不执行真实模型任务。

## 启动

需要 Node.js >= 22.12.0、Git 和 Electron，以及已安装依赖的 `frontend/`。构建会把已有 React 聊天页面打包进桌面端，运行聊天不依赖 Vite。当前 Mac 已有 Electron 43.3.0，启动器默认复用 `~/.dsh/electron/Electron.app/Contents/MacOS/Electron`。其他位置通过 `CAICAI_ELECTRON_PATH` 指定可执行文件；本项目不会自动替换已有 Electron。

从项目根目录执行：

```sh
cd frontend
npm ci
cd ../desktop
npm ci
npm run setup
npm run build
npm start
```

`setup` 将固定提交下载到 `.cache/upstream`，不跟踪移动的 main 分支；`build` 校验提交及缓存工作区后构建共享动画核心和菜菜入口，复制运行时及素材，不复制展示用预览 GIF。缓存有本地改动时拒绝构建。

首次启动显示桌宠及控制面板。点击“和菜菜聊天”、Cmd + 点击桌宠，或使用右键“和菜菜聊天” / “对话”及 L 键，可打开独立聊天窗口；普通点击仍保留上游动画交互。在聊天页顶部点击“桌宠设置”返回控制面板。关闭聊天窗只会隐藏，正在生成的回复和语音继续，再次打开保留原窗口与连接；托盘退出才结束应用。退出关闭桌宠自己的本机服务，不关闭手动启动的 FastAPI 或 Vite。

控制面板可选择形象、查看后端状态并打开现有网页工作台。首次使用须按根 README 准备 `backend/.venv`、安装后端依赖并配置 `backend/.env`；之后桌面端会自动连接或启动后端，无需另开终端运行 uvicorn。默认地址为 `http://127.0.0.1:8000`；桌面聊天无需启动网页开发服务器。仅在使用“打开网页工作台”时需要 Vite，默认地址为 `http://127.0.0.1:5173`。通过 `CAICAI_BACKEND_URL`、`CAICAI_WORKBENCH_URL` 可覆盖，仅接受本机 HTTP origin。

### 后端自动启动与退出

- 启动时检查 `/health` 的菜菜服务标识；已有可用服务就复用，不要求本地 Python 存在。旧版后端没有服务标识时，需要先手动重启更新后的后端。其他程序占用端口时明确报错，不终止占用者，也不悄悄切换到另一套数据。
- 没有服务时，使用 `backend/.venv/bin/python` 启动 `backend/desktop_server.py`，工作目录固定为 `backend/`，沿用已有 `.env`、数据库、模型配置及音色。只启动单进程，不开启 reload。自定义解释器通过 `CAICAI_BACKEND_PYTHON=/absolute/path/to/python` 指定；只连接已有服务可设置 `CAICAI_BACKEND_AUTOSTART=0`。
- 面板定期显示连接中、启动中、已连接或失败，并区分“由菜菜启动”与“复用已有后端”。缺少 Python、依赖或有效配置，端口占用、20 秒启动超时及运行中断连均有提示；修复后点击“重试连接 / 启动”。不会自动重启失败进程或重发聊天。
- 关闭聊天或控制面板保留后端；从托盘退出，或启动终端收到 SIGINT / SIGTERM 时，先停止菜菜自己启动的后端，再退出桌面端。后端进程组优雅退出超过 8 秒会被强制清理，包含其 TTS 子进程；外部启动的后端始终不归菜菜关闭。
- Electron 异常退出时，后端通过 stdin 管道断开识别宿主消失并退出；清理卡住时有 10 秒兜底。进程组清理已在 macOS 验证，其他系统尚未验收。
- 管理员令牌仍由用户在聊天窗口输入；不自动读取并注入窗口，也不复制模型密钥。面板只展示固定诊断，不回显 Python 堆栈或配置值。后端源码、Python 环境与依赖仍需本地准备，本轮不包含独立安装包。

### 聊天与声音

1. 等控制面板显示“后端已连接”，在独立聊天窗口填写 `backend/.env` 中的 `ADMIN_TOKEN` 并连接。令牌只保存在该窗口的会话存储中，隐藏窗口会保留，退出程序后需要重新连接；不自动读取环境文件或复制模型密钥。
2. 创建桌面会话，选择已有中转站、模型和聊天人设并保存。桌面与网页测试会话分开，模型站点和音色共用同一后端。
3. 在聊天设置选择音色并保存，回复固定为文字与语音同步生成；开启“自动朗读”即可播放。复用既有本地 VoxCPM2 与缓冲播放；也可手动朗读及单独重试语音。
4. 正在生成文字时显示思考；等待音频时显示准备语音；仅音频实际开始播放时显示说话，并在大肥鱼的原生聊天气泡显示当前语音段文案；下一段实际开始后才换字，预加载不会提前替换。同一说话阶段换段不重复启动动画。暂停、结束、停止及切换页面会更新状态。状态动画从当前角色已有 `events.workStatus[0]` / `events.whisper[0]` 选择，缺少相应动作时仅显示状态气泡并保留原生动画，不要求重做角色素材。睡眠或交互锁占用时尊重上游门禁。

聊天设置不再显示“回复方式”和“语音表达提示词”；保存前必须选择音色，旧纯文字会话保存后也会切换为文字与语音同步生成。已有表达提示词保留，当前语气跟随参考录音。

正式发送接口为 `POST /api/v1/desktop/conversations/{id}/messages` 和对应 `/stream`，仅接受 `channel=desktop`，生产环境可用并继续要求管理员鉴权。网页保留原有 debug 通道。桌面 HTTP 代理只转发允许的路径与方法，逐段转发 SSE 和二进制音频，不转发桌宠令牌或 Cookie，也不跟随后端重定向。后端离线时显示连接提示，不会自动重发消息。

### 等待时的语音回应

聊天设置新增“思考与等待语音”区域：按会话保存“等待时语音回应”开关、思考提示语和语音合成等待提示语，每条 1～100 字，可自行修改。保存设置只保存配置；点击“保存并生成提示语音”会先保存，再使用当前朗读音色生成两条短句正文。生成过程中显示进度，失败后可手动重新生成。每次重新生成都会删除该会话上一版的两条任务记录和 WAV 文件，不保留旧版本，也不影响其他会话或正式回答的语音。上一轮仍在合成时禁止重复生成。

两条短句与正式回答使用同一个会话音色与参考录音。当前 VoxCPM2 复刻路径不传自由文本语气指令，避免底层库把指令拼回正文并念出；已有提示词保留为配置，界面注明暂不参与合成。已生成的语音保存在本地，进入聊天时只读取，发送消息也不会重新合成。修改音色、语气或提示语并保存后，旧配置的短句立即停用，必须手动生成新语音。生成失败后旧文件也不会恢复；未生成时保持安静，不回退系统音色。首次生成可能需要加载模型。短句和正式回复共用本地推理引擎，排队中的正式语音优先，已开始的单次推理不会被抢占。

需在聊天设置选择音色并保存，同时开启当前会话的“等待时语音回应”和顶部“自动朗读”。新发消息后，思考持续约 180 毫秒播放思考提示；文字生成结束且仍等待语音约 1.2 秒时播放等待提示。每轮每阶段最多一次，快速完成时跳过。提示与正式回答共用音频输出，实际出声时联动说话状态；回答就绪、暂停朗读、切换页面 / 会话或播放其他音频时立即停止提示。收起聊天窗保留连接与播放。音频使用现有鉴权下载接口，不出现在音色试听记录中，删除会话或音色时清理。升级会清理早期无会话归属的自动缓存，随后按新流程手动生成。

## 数据与角色包

默认数据在 `.data/`，通过 `CAICAI_DESKTOP_DATA` 可修改。桌面端使用独立 DSH_HOME 和 Chromium profile，不改写 `~/.dsh/dsh-pet` 的已有配置。`.cache/`、`.data/`、`dist/` 和依赖均不入 Git。沿用固定上游的角色格式：

```text
.data/dsh/dsh-pet/
  main-config.jsonc                 默认角色及全局偏好
  main-animation/webm/             默认角色的自定义素材（可选）
  pet/
    my-pet-config.json             新角色配置，也支持 .jsonc
    my-pet-character.png           参考图（可选）
    my-pet-animation/              透明 VP9-alpha WebM 动画（额外角色直接平铺）
      <动作名>.webm
```

新增角色只需素材与配置：

1. 按上游角色包格式准备 `<种类>-config.json(c)` 和对应动画目录，给 `pets[]` 实例设置全局唯一 `id`、显示名 `name`，首次安装建议 `display: "none"`。
2. 配置里的动画名须与对应 `.webm` 文件名一致，沿用上游完整动画配置结构；不要直接继承默认形象的动作名却缺少相应素材。
3. 将文件放进上述 `pet/`，保留该角色的作者、来源与许可说明。
4. 重新打开控制面板即可发现角色，选择后点击“切换形象”。上游 `/pet-display` 写回对应配置文件并重建窗口，重启继续按保存的 display 显示。

切换仅修改桌面显示位，保留浏览器显示位，不改聊天、人设、音色或任务。托盘保留上游多开能力。配置、物理、动作链、菜单和角色素材查找均复用上游。

当前提供原有默认大肥鱼形象。临时验证角色、素材生成脚本与自动安装逻辑已按用户要求移除；角色包加载、切换、配置保存和重启恢复能力仍保留。后续可直接按上述原生角色包格式加入用户提供的形象，无需修改核心代码。

固定上游对额外角色直接查找 `pet/<种类>-animation/<动作>.webm`，**不会查找其下的 `webm/` 子目录**；`main-animation/webm/` 只适用于主角色。此前文档将两种路径混用，已通过真实素材加载验收纠正。

低成本制作流程见固定缓存中的 `MAKE-YOUR-OWN-PET.md` 和 `CONFIG.md`：参考图 → 绿幕动作视频 → 抠像与归一化 → VP9-alpha WebM → 原生角色配置。不要求 Live2D，不需要修改菜菜或桌宠核心代码。

## 与上游的边界

- 上游源码保持原样；通过独立入口复用 host、standalone context 和 Electron helper。
- 构建副本调整 helper 的 userData 路径，并把对话入口与菜单首项接到菜菜聊天；共享动画核心从固定源码构建。适配点有固定源码锚点校验，上游缓存本身不修改。
- 控制面板使用独立隔离 session，避免与 file 渲染页的鉴权注入冲突。
- 不另存模型配置、不调用上游云端语音；所有聊天及音色功能复用菜菜后端。桌面聊天和控制面板均隔离 Node、禁用任意新窗口，并限制页面导航。
- 默认形象为非商业授权素材；代码 MIT 与素材许可分别遵守，见 THIRD_PARTY_NOTICES.md。
