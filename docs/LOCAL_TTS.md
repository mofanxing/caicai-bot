# 本地音色复刻使用说明

更新：2026-11-17。已在 Apple M1 Pro / 32 GiB / macOS 26.6.2 / Python 3.12.14 验证。

## 当前能力

后台“音色与语音”支持参考录音上传、删除、原音播放、文字试听和表达提示词；“聊天测试”支持流式文字与语义分段语音同步生成，合成时后续文字可继续生成。开启聊天顶部的“自动朗读”，默认采用“流畅优先”缓冲后顺序播放，也可切换“低延迟”就绪即播；支持暂停、重新朗读、跳过或重试失败片段。历史消息不会自动重播。语音失败保留文字，重试只重新合成音频。

引擎为 MLX-Audio 0.6.5 + VoxCPM2-4bit，参考音频和表达指令同时传给模型。当前已安装在本机，首次加载按需触发。参考音色是推理时条件，不需要另行训练模型；实际相似度、口音和情绪效果需要用目标录音试听调整，不保证完全复现。

## 安装或迁移

当前实现面向 Apple Silicon Mac；未适配 Windows、Linux 或 Intel Mac。推荐使用已验证的 Python 3.12，系统自带 Python 3.9 不适用。在项目根目录执行：

    cd backend
    .venv/bin/python -m pip install -c constraints.txt -e '.[dev]'
    cd ..
    backend/.venv/bin/python backend/local_tts/setup.py

setup.py 创建 backend/.tts-venv 独立环境，按固定依赖约束安装，并下载约 2.3 GB 模型；首次安装需要网络。已存在的后端环境需先按根 README 建立。模型固定为 mlx-community/VoxCPM2-4bit，revision 为 dc9e5c187858da5f4a13dc4c247e297339216381。

重启原有后端并刷新前端。不要用多个 Uvicorn worker；当前队列并发为 1。首次生成有模型加载和编译开销，可能需数十秒或数分钟。后续模型常驻，实际速度取决于文本、录音与机器负载。

可选环境变量见 backend/.env.example：SPEECH_DATA_DIR、LOCAL_TTS_PYTHON、LOCAL_TTS_MODEL_DIR、LOCAL_TTS_TIMEOUT_SECONDS。默认路径适用于从 backend 目录启动。模型和音色数据位于已被 Git 忽略的 backend/data/tts；独立环境同样被忽略。现有 Docker 镜像不包含 Mac MLX 运行环境。

## 页面使用

1. 打开后台并连接，进入“音色与语音 → 添加音色”。
2. 填写名称，选择 3～30 秒单人、少噪声、无背景音乐的 WAV 或 MP3。使用本人或已获授权的录音。
3. 可填写默认语气，例如“温柔自然，语速稍慢”。“录音文字备注”仅用于记录，当前推理不使用转写。
4. 保存后选择音色，输入要说的话和语音表达提示词，点击“生成并自动试听”，完成后自动播放，可暂停、继续和重播。重新进入页面恢复的历史试听不会自动播放。
5. 回到“聊天测试”，在设置中选择“文字 + 语音同步生成”、音色与表达提示词并保存，再打开顶部“自动朗读”。文字逐步出现，语音分段进入后台队列；默认“流畅优先”会先缓冲，可用顶部“朗读策略”选择低延迟。关闭自动朗读后可手动点击“开始朗读”；已选择音色的纯文字会话也可点击“用当前音色朗读”。
6. 自动朗读初次使用默认开启，手动关闭后保存在当前浏览器。发送下一条消息、切换会话或离开聊天页会停止当前朗读；生成任务继续在后台完成。点击发送、开启朗读或生成试听时同步准备并恢复同一个音频输出上下文，生成完成后复用该输出自动播放。浏览器若仍限制声音播放，会显示提示，点击“开始朗读”即可继续。

聊天角色提示词控制回复内容；语音表达提示词控制表达。表达指令与台词分开输入，不会被拼成要朗读的正文。可对比“开心活泼，语气轻快”“平静清晰，自然叙述”等指令；效果取决于模型。

### 思考与等待提示语音

聊天设置可按会话开启“等待时语音回应”，编辑思考与语音合成等待阶段的两条短句，每条 1～100 字。点击“保存并生成提示语音”后，使用当前音色、参考录音和生效的语音表达提示词生成；每次生成会删除该会话上一版的两条任务及音频。仅保存设置、进入聊天或发送消息不会触发合成；修改音色、表达提示词或短句后，需要手动重新生成。未生成或生成失败时保持安静，不回退系统音色。

播放需同时开启会话开关、顶部“自动朗读”和语音回复模式。每轮每阶段最多播放一次，快速完成时跳过；正式回答开始、暂停朗读、切换会话 / 页面或其他音频播放时停止提示。提示语音与回答共用本地推理引擎，排队中的正式回答优先，已经开始的推理不会被抢占。桌面端收起聊天窗仍保留连接与播放。隔离 Electron 验收使用静音 WAV 夹具，真实 VoxCPM2 的音色与交互节奏仍需试听。

### 长文本音色变化

流式聊天首段至少累计约 32 字符再选择完整句末，后续至少约 60 字符合并短句，单段最多 120 字符；超长句优先在逗号等分句处切开。整条回复不足门槛时，在文字生成结束后直接合成，不会一直等待。“你好呀。”之类的短开场不再单独抢先生成。试听和手动生成仍按最多 120 字分段。语音最多覆盖回复的前 600 字，超出时页面明确提示，文字全文保留。

较大的语义段减少了模型在很短片段间重新起句的次数，但当前实现仍逐段独立合成，没有传递上一段声学上下文，无法保证段间音高、情绪完全一致。缓冲只改善播放连续性，不会修复已生成音频本身的语气错误。

长文本按最多 120 字符分段，每段都独立使用同一参考录音与表达指令生成，再拼接音频；模型没有延续上一段的声学上下文，因此同一音色仍可能在段落间出现音高、气声或语速变化。2026-11-17 调整为优先保留完整句子、合并可容纳的短句，超长句优先在逗号等位置切分，并在每段生成前重置随机种子，减少不必要的重启、句中截断和前段随机采样对后段的影响。这些措施不能保证主观音色完全一致，实际改善需要用同一录音和长文本对比试听。

试听时优先选择音质清晰、单人且说话方式稳定的参考录音，先以空白表达指令生成作基线，再尝试温和的语气变化。已有音频文件不会自动更新，代码变更后需重启后端，在音色页重新生成试听。

### 延迟优化

2026-11-17 增加了文字流与语音合成重叠执行、按段顺序播放，状态检查间隔从聊天旧播放器的 1.5 秒缩短为 0.5 秒。模型进程内最多缓存 4 份参考音频 VAE 编码，文件修改后失效；连续分句不再每次清空 MLX 分配器缓存。保持原有 10 步推理参数与音色模型，没有通过降低推理质量换速度。首次模型加载和 GPU 编译仍需等待；这些改动不代表已完成真机性能对比，不能承诺固定提速比例。

模型接口支持 Chat Completions 流式输出，也保留服务端明确要求时切换 Responses 的适配；返回普通 JSON 的网关仍可显示回答，但需要等它返回全文，无法提前显示文字。流断开或输出不完整会保留已收到的文字并标记失败，不会自动重发模型请求。

### 连续朗读与首播等待

- 默认“流畅优先”：通常先准备至少两段、累计至少 8 秒的已解码音频再开始，短回复全部就绪后直接播放。用已完成任务的总合成耗时除以总音频时长估计速度，若比值大于 1.1，则等待整条回复的任务结束再开播，避免生成速度跟不上播报导致反复断声。门槛为启发式策略，不是性能承诺。
- “低延迟”：首段就绪后立即播放，保留更快的首次出声，但设备合成跟不上时仍会等待后续语音。策略选择保存在当前浏览器。
- 当前段及后两段提前下载和解码，最多保留三段音频缓冲；预载下一段不会中断或重置当前段。
- 当长期合成速度慢于播放速度时，有限的首播缓冲无法保证任意长回复连续播放；需要增加首播等待，或换用更快的语音模型/硬件。当前没有通过降低推理步数换取速度。

## 限制与数据

- 页面文件上限 20 MB，浏览器在本机转换成单声道 16 kHz / PCM16 WAV，无需 ffmpeg；API 直接上传只接受不超过 10 MB 的 16-bit PCM WAV、1～2 声道、8～48 kHz。
- 一次合成最多 600 字符，表达提示词最多 500 字符。流式聊天超过 600 字时明确提示只朗读前 600 字，全文保留；旧非流式接口对超长语音仍返回任务失败。
- 新任务受 8 个排队或运行任务限制；同一条流式回复的分句共享该回复的容量，受 600 字总量限制，避免长回答后半段因自身分句排满队列而失败。推理始终单线程排队，不自动重试合成失败。生成耗时及音频时长写入各分段记录。
- 运行中任务阻止相关音色/聊天删除。删除音色会删除参考录音与生成文件，并将绑定会话恢复文字回复；聊天文字保留。删除聊天会清理其语音。删除不影响已有备份。
- 服务启动时恢复排队任务，将上次运行中断的任务标为失败，等待手动重试。当前不提供运行中取消。
- 推理强制使用离线模式，语音数据不发送云端 TTS；首次安装下载依赖和模型。聊天文字仍按独立的聊天模型配置调用，聊天模型费用与数据流向不受影响。
- 音频和音色接口要求管理员 Bearer 令牌。前端通过鉴权请求取得 Blob 播放，不将令牌放在音频 URL 中。此项目是单管理员本地应用，没有多用户租户隔离。
- 桌宠已复用文字聊天、语音播放及状态动画；当前没有语音识别、持续监听或微信语音气泡，这些继续按路线图后续实现。

## 验证

常规回归（不需要加载模型）：

    cd backend
    .venv/bin/pytest -q
    .venv/bin/ruff check .

真实本地模型验证（需要已安装模型、Mac GPU，使用临时数据库和官方示例参考录音）：

    cd backend
    .venv/bin/python local_tts/verify.py

结果保存在 backend/data/tts/validation/api-report.json。2026-11-16 验证通过上传 → 试听 → 鉴权获取音频 → 聊天音频 → 重复请求去重 → 删除清理。预热后示例：3.84 秒试听音频耗时 4.605 秒，3.04 秒聊天音频耗时 3.426 秒；这不是固定性能承诺。另经浏览器实际上传、生成和播放验证，3.20 秒音频耗时约 4.0 秒。验证使用官方示例，不代表已评估用户目标音色的主观相似度。

2026-11-17 新工作进程真机冒烟验证：取官方 test_en.wav 前 5 秒作为参考，连续生成“你好呀。”和“很高兴见到你。”，均返回有效音频。首次总等待 5.046 秒（其中合成 3.150 秒，音频 0.960 秒），第二句等待 1.952 秒（合成 1.951 秒，音频 1.600 秒）。这验证了新缓存与连续生成链路可用，因文本和参考时长不同，不能与旧数据直接计算提速比例；临时音频已自动清理。

## 接口

全部要求管理员鉴权；任务状态为 queued / running / completed / failed。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/v1/speech/status | 运行环境和模型状态 |
| GET / POST | /api/v1/voices | 列表 / multipart 上传 name、audio、可选 style_prompt、reference_text |
| GET | /api/v1/voices/{id}/reference | 原始参考音频 |
| DELETE | /api/v1/voices/{id} | 删除音色并解除绑定 |
| POST | /api/v1/voices/{id}/previews | text、可选 style_prompt，返回 202 和任务 |
| GET | /api/v1/speech/jobs | 最近 20 条试听任务 |
| GET / POST | /api/v1/conversations/{cid}/speech-feedback | 读取当前会话提示语音 / 手动替换生成两条短句，POST 返回 202；GET 不触发合成 |
| GET / DELETE | /api/v1/speech/jobs/{id} | 查询 / 删除已结束任务 |
| GET | /api/v1/speech/jobs/{id}/audio | 已完成音频 |
| POST | /api/v1/speech/jobs/{id}/retry | 重试失败分段或重新生成丢失文件，复用原任务 ID |
| POST | /api/v1/debug/conversations/{cid}/messages/stream | 管理员调试 SSE，事件 start / delta / speech / notice / done / error |
| POST | /api/v1/conversations/{cid}/messages/{mid}/speech | 只生成或重试该回复的音频 |

会话设置增加 voice_id 和 voice_prompt；reply_mode=both 时自动创建音频任务。消息的 speech_job_ids 按生成顺序返回全部语音分段，speech_job_id 保留首段兼容旧客户端；非流式调用通常只有一段。重复 external_id 请求复用原记录和语音任务。关闭网页后服务端仍会继续完成已接收的聊天，避免重发产生重复调用。
