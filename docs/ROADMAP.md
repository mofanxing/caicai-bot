# 菜菜桌宠与任务调度中心规划

记录日期：2026-11-16（Asia/Shanghai）

状态：M0 本地语音已实现并完成真实链路验证；目标音色主观效果待用户试听。本文区分现有能力、建议方案和待确认选型；未勾选事项不代表已经实现。

## 1. 产品目标与优先级

将菜菜做成“桌面上的 AI 助理 + 后台任务调度中心”。现有项目继续作为模型接入、配置、会话和任务能力的底座。

目标体验：菜菜平时待在桌面上，用户可以与她聊天；用户交代工作后，她创建任务、调度 harness、显示执行进展，并交付结果。后续支持语音聊天和语音派发任务。

优先顺序（2026-11-16 调整）：后台音色复刻与聊天播报 → 桌宠与文字聊天 → 真实任务执行闭环 → 语音输入 → 陪伴体验与多执行器 → 微信。微信接入明确后置，已有预留代码保留。

本轮需求：先在后台上传参考录音，创建可用于合成的音色，输入文字试听，再让聊天回复使用该音色播放。语气希望通过提示词控制，需要选用支持相应指令的语音模型并验证实际效果。用户已确定采用本地语音模型；本地部署、选型验证与功能设计见 [音色复刻与聊天播报方案](VOICE_PLAN.md)。

参考与术语边界：

- “大肥鱼”暂作为桌宠交互形态的参考，具体产品和期望动作尚未核对，不据此假定功能或技术实现。
- “DeepSeek harness”暂按“由 DeepSeek 驱动的代理执行器”理解；具体仓库、程序、版本及接口待确认。
- 模型 API 负责模型推理；harness 负责工具调用循环、工作目录、命令执行和结果验证；菜菜负责交互、派发、状态和汇报。

## 3. 建议架构

```text
桌宠 / 聊天窗 / 管理工作台 / 未来微信
                  ↓
          菜菜对话与意图处理
         聊天、记忆、创建任务
                  ↓
              任务调度中心
       排队、进度、取消、结果、记录
                  ↓
             Harness 执行器
       读写项目、运行命令、验证结果
                  ↓
            DeepSeek 等模型
```

所有入口复用同一套对话与任务能力。桌宠显示状态和结果；后台服务持有任务记录，执行器在独立 worker 中处理任务。

### 桌面与工作台

- 建议第一版采用 Electron + React，保留 Python 后端；这是建议选型，尚未完成技术验证。
- 暂按当前 Mac 环境优先落地；其他系统支持范围待确认。
- 桌面进程统一管理本地后端启动、连接和退出，明确收起窗口与退出程序的不同语义。
- 桌宠采用透明、无边框、可拖动、可置顶的小窗；点击打开聊天，菜单进入设置或任务列表。
- 工作台复用现有前端，管理模型、角色、音色、执行器、项目和任务历史。
- 初期使用简单二维动画素材；Live2D、换装和复杂动作后置。
- 程序状态驱动待机、倾听、思考、说话、执行中等动作。

### 对话与记忆

- 新增正式聊天接口与桌面通道，避免桌宠依赖生产环境禁用的 debug 接口。
- 增加流式回复与事件推送；具体传输协议实施时选定。
- 区分普通聊天和任务请求；缺少必要参数时补问，派发后显示任务卡片。
- 人设、用户偏好与任务状态分别保存，任务进度不依赖聊天窗口的上下文。
- 模型提供的路由或任务参数需经服务端校验后才能执行。

### 任务调度与执行

- 第一版采用持久化任务表 + 独立 worker，单执行器、单任务并发。
- 每个任务绑定项目目录、目标、执行器和状态，记录进度事件、结果及产物引用。
- 状态包含排队、执行中、等待确认、成功、失败和已取消；状态转换与原因需可追溯。
- 支持取消、超时、中断识别；取消需传递到实际执行进程，不能只更新界面。
- 收起桌宠、关闭聊天窗后任务继续；程序退出或重启后识别中断任务，不盲目重放有副作用的操作。
- 约束执行目录、权限及敏感操作，避免未经校验的模型文本直接变成系统命令。
- 优先适配选定的成熟 harness，复用其执行循环；适配器统一启动、事件接收、取消和结果读取。
- 区分任务记录与某次执行尝试，后续重试保留历史并明确是否可能重复产生副作用。
- 调整当前中转站互斥机制，拆分配置变更保护与请求并发控制，避免后台工作阻塞正常聊天。

### 语音

- 前置的第一步：上传参考录音 → 创建音色 → 输入文字试听 → 聊天回复使用该音色播报。
- 语音输入在后续增加：按住说话 → ASR 转文字 → 对话或创建任务 → TTS 回复。
- 支持字幕、音色选择、停止播放；连续收音、自动断句、打断和唤醒词分后续迭代。
- 语音识别、语音合成、聊天模型与任务模型分别配置。
- 复用对话与任务接口，语音只增加输入输出方式。

## 5. 首个可用版本边界

当前先交付 M0 的后台闭环：“上传参考录音 → 创建音色 → 试听 → 聊天播报”。随后首个桌面任务闭环覆盖 M1 + M2：一个桌宠形象、文字聊天、一个执行器、一个任务面板，复用 M0 的语音输出能力。语音输入在 M3 加入。

初期不扩展复杂多代理调度、Live2D 换装、持续监听和微信接入。SQLite 与单 worker 先满足本地使用；后续根据并发和部署需求决定是否引入额外队列及服务。
